# 🖥️ 作業系統進程排程教學工具 (OS Process Scheduling Simulator)

歡迎來到作業系統 (OS) 進程排程的互動學習工具！這個工具旨在幫助你理解 CPU 是如何決定「誰先執行、誰後執行」的，並且讓你親眼看到不同演算法對系統效能（特別是等待時間）的影響。

## 🎯 為什麼我們需要排程 (Scheduling)？
想像 CPU 是一個只有一個收銀員的超市結帳台，而 Process（進程）就是排隊結帳的客人。如果我們不制定好的排隊規則，可能會導致買一瓶水的客人被買滿整車雜貨的客人卡住很久。排程演算法的目的，就是在「公平」與「效率 (最短等待時間)」之間取得平衡。

---

## 🔍 核心演算法介紹與觀察重點

### 1. 先到先得 (FCFS - First-Come, First-Served)
* **運作方式**：誰先排隊，誰就先用 CPU，直到用完為止（非搶佔式）。
* **💡 觀察重點 (護航效應 Convoy Effect)**：
  請在工具中選擇 **「長到短 (觀察護航效應)」** 情境並模擬。你會發現，執行時間很短的 P4 被迫等待 P1 執行完畢，導致整體的平均等待時間非常高。

### 2. 最短作業優先 (SJF - Shortest Job First)
* **運作方式**：檢查隊列中誰需要的最少時間，就讓誰先執行。
* **💡 觀察重點 (最佳解與平局)**：
  SJF 在數學上保證了**最短的平均等待時間**。
  但如果兩個進程需要的時間一樣長怎麼辦？請選擇 **「特殊情況：相同執行時間」** 情境。你會發現系統無法用時間區分時，會退化成 FCFS，直接比較 Process ID (P1 優先於 P2)。

### 3. 輪轉法 (RR - Round Robin)
* **運作方式**：給每個人一個固定的「時間片 (Time Quantum)」。時間到了如果還沒做完，就強制暫停，排到隊伍最後面。
* **💡 觀察重點 (響應性 vs 效率)**：
  RR 的平均等待時間通常比 SJF 長，但它確保了**沒有人會等太久才開始**（高響應性）。現代作業系統（如 Windows/macOS）多半基於此概念。
  * **動手玩**：嘗試改變 `Time Quantum` 的大小。設為 `5` 時，它是不是長得很像 FCFS？設為 `2` 時，雖然大家都能很快輪到，但 CPU 一直在切換任務。

## 🧮 等待時間 (Waiting Time) 是怎麼算的？

工具右下角會顯示詳細的計算過程，這裡為你拆解基本公式：

* **對於 FCFS / SJF (不中斷的演算法)**：
  `等待時間 = 開始執行的時間 - 到達時間`
  *(註：本模擬中所有進程的到達時間皆為 0)*

* **對於 RR (會中斷的演算法)**：
  因為進程會斷斷續續地執行，我們不能只看「第一次開始的時間」。
  `等待時間 = 完成時間 (最後結束的那一刻) - 到達時間 - 實際執行時間 (Burst Time)`

## 🚀 如何使用本工具
1. 從左側面板選擇一個 **情境 (Scenario)**。
2. 選擇你想觀察的 **排程演算法 (Algorithm)**。
3. 如果選擇 RR，可以調整 **時間片 (Time Quantum)**。
4. 點擊 **「開始模擬 (Simulate)」**，觀察右側的甘特圖動畫與下方的數學計算過程！
